# chicken_manu

Chicken Menu, 치킨메뉴, ... : 리듬게임·음악게임의 매체를 조사하고, 공유·보존하는 도구

## 용어: 매체와 에셋

- **매체**: 리듬게임·음악게임의 플레이를 규정하는 데이터. 채보(chart, 譜面, 보면, beatmap, simfile 등)가 대표적이다.
- **에셋**: 매체가 **참조하는** 파일(음원, 키음, 이미지, 영상 등). 매체에 속하지 않고 바깥에 있다.
- 포맷마다 부르는 이름이 다르다. 출처가 쓰는 원어는 그대로 두고, 대응 관계는 따로 기록한다.
- 매체의 구성과 형식은 나중에 정의한다. 그때 에스펜 올셋과 고든 체레자의 사이버미디어 모델을 참조할 예정이다(문헌은 `미확인`).
- "BMS, ..."라고 쓴 곳의 `...`은 BMS 외의 다른 포맷도 뜻한다. BMS는 가장 먼저, 가장 깊이 조사한 포맷일 뿐이다.

## 목적

목적은 두 방향이다. 서로 먹여 살린다.

### 1. 매체의 형식 조사

- 리듬게임·음악게임의 매체가 어떤 형식으로 존재하는지 목록으로 만들고, 근거와 함께 기록한다.
- 대상은 BMS 계열, 기타 히어로 계열(`.chart`, `.mid`), osu!(`.osu`), StepMania(`.sm`, `.ssc`) 등의 채보 포맷과,
  이를 읽고 쓰는 구동기·에디터·파서, 형식을 설명하는 규격이다.
- 평가나 통합보다 **무엇이 존재하는지**를 먼저 기록한다.
- 현황: BMS 계열이 가장 깊이 조사돼 있다. 다른 계열은 주소와 평가만 있다.

### 2. 매체의 공유·보존 도구의 명세와 구현

- 매체와 매체가 참조하는 에셋을 잃지 않고 옮기고 찾을 수 있게 하는 **데이터 포맷과 메타데이터 스키마**를 정의한다.
  묶음, 패턴(채보), 파일, 제작 참여자, 파일 식별(해시, IPFS CID), 파일 참조를 다룬다.
- 정의한 스키마로 매체를 도서관의 목록처럼 관리하고 서로 공유·배포하는 **도구**(Rust)를 구현한다.
  공유는 처음에 Rust의 libp2p로 IPFS를 쓰려 했으나, 기술 채택을 위한 조사가 더 필요하다.
- 현황: DB 스키마 설계서, BMS 문법 초안, 기술 채택 사전 조사까지 했다.

### 두 방향의 관계

- 1의 조사 결과가 2의 요구사항이 된다. 어떤 포맷을 지원할지, 파일 참조를 어떻게 읽을지가 스키마를 정한다.
- 2에 필요한 것이 1의 조사 질문이 된다. 파일 참조, 경로, 인코딩, 채보 단위, 묶음 단위, 식별이 그 질문이다.
