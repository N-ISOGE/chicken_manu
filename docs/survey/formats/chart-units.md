## 1. 비교할 단위

파일 하나에 채보가 몇 개 들어가는지, 여러 파일이 어떤 묶음을 이루는지, 관련 자료를 어떻게 찾는지를 비교합니다. 이 구분은 매체를 목록에 기록하고 연결을 유지하며 옮기는 데 필요합니다.

- **채보 단위**: 난이도·트랙·모드 등을 구분해 하나의 채보를 찾는 단위입니다.
- **파일 단위**: 바이트로 저장된 개별 파일입니다. 한 파일이 여러 채보를 담을 수 있습니다.
- **묶음 단위**: 채보와 곡 정보·음원·이미지 등을 함께 취급하는 폴더·압축 파일·컨테이너입니다.

파일·채보·묶음은 일대일로 대응하지 않습니다. 한 파일 안에 여러 채보가 들어가거나, 여러 채보가 같은 음원·이미지를 참조할 수 있습니다. 트랙·난이도·모드도 형식마다 채보를 나누는 방식이 다르므로 같은 단위로 간주하지 않습니다.

참조 필드의 존재와 해당 자료의 필수 여부는 서로 다른 질문입니다. 아래 표의 필드 목록을 스키마의 필수 값 제약으로 그대로 옮기지 않습니다.

## 2. 단위와 참조 방식의 비교

이 표는 파일 내부의 채보와 외부 자료 연결을 비교하는 출발점입니다. **확인한 내용과 대조할 항목을 마지막 열에서 구분합니다.** 필드 이름을 나열한 것만으로 경로 해석이나 필수 여부까지 확인한 것은 아닙니다.

3·4절의 소스 관찰은 해당 판본에 한정합니다. 문서에서 확인한 규칙, 특정 구현이 읽는 규칙, 실제 파일을 실행한 결과는 각각 구분해야 합니다. 이 문서에는 게임 실행 결과를 포함하지 않습니다.

| 대상                        | 채보·묶음의 구별                                | 관련 자료 참조                                                           | 근거·남은 확인                                                                                                                                  |
| --------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| BMS 계열                    | 파일과 분기별 해석 결과를 구별                  | `#WAVxx`, `#BMPxx` 등의 슬롯과 파일 경로                                 | [BMS 문법][nav-1]. 분기가 있을 때 채보를 식별하는 정책은 별도 검토                                                                              |
| StepMania `.sm`·`.ssc`      | 파일 안에 복수 채보 블록                        | `#MUSIC`, `#BACKGROUND` 등의 태그                                        | 3절의 로더 소스. 곡별·채보별 타이밍과 재선택을 구별                                                                                             |
| `.chart`·보컬 MIDI          | 파일 안의 트랙·난이도와 개별 채보의 관계 확인   | 곡 정보와 파일명 관행까지 함께 조사                                      | 3·4절은 YARG 구현의 일부. Clone Hero 등 다른 구현과의 동일성 미확인                                                                             |
| osu! `.osu`·`.osz`          | 개별 difficulty와 곡 묶음을 구별                | `AudioFilename`, `[Events]`의 배경·영상                                  | [osu! 파일 형식 문서](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_%28file_format%29). 3절의 mania 규칙과 별도로 참조·경로 규정 대조 필요 |
| bmson                       | 채보와 참조 자료를 구별                         | `info`의 이미지·미리듣기, `sound_channels[].name`, `bga_header`의 파일명 | [1.0.0-beta 명세](https://bmson-spec.readthedocs.io/en/master/doc/index.html). 정확한 중첩 경로·필수 여부·판본별 차이를 대조해야 함             |
| KSH `.ksh`                  | 채보 파일과 곡·이미지를 구별                    | `m`은 곡 파일명이며 `;`로 복수 지정 가능. `jacket`은 이미지 파일명       | [KSH 명세 Header](https://kson.dev/docs/format-spec/ksh_format/#header), 2026-10-16 본문 확인                                                   |
| Beat Saber                  | `Info.dat`와 characteristic·difficulty 항목     | 곡·커버·비트맵 파일의 연결                                               | [BSMG 맵 형식 안내](https://bsmg.wiki/mapping/map-format.html). 커뮤니티 자료이며 대상 판본별 스키마 대조 필요                                  |
| Quaver·DTX·ADOFAI·`.sng` 등 | 채보·묶음의 관계를 이 표에서 아직 대조하지 않음 | 개별 필드와 경로 규칙 추가 확인                                          | [조사 대상 파악][nav-3]의 후보이며 이 표에서는 개별 규칙을 확정하지 않음                                                                        |

### 참조 자료를 읽기 위한 인코딩

KSH 명세의 [Encoding 절](https://kson.dev/docs/format-spec/ksh_format/#encoding)은 UTF-8 BOM을 권장하고 KSM의 BOM 기반 판별을 설명합니다. 이 문서에서는 명세의 설명을 확인했으며 KSM 실행으로 확인한 것은 아닙니다.

## 3. 특정 판본에서 관찰한 해석 규칙

아래는 2026-10-14에 특정 판본의 소스·문서에서 확인한 정적 관찰입니다. 파일 선택, 파일 안의 채보 재선택, 노트 해석을 구별해 읽습니다. 같은 확장자를 읽더라도 이러한 규칙이 다르면 동일한 해석 결과를 전제할 수 없습니다.

### StepMania: 파일 선택과 파일 안의 채보 구별

근거: [stepmania/stepmania, `825467bc`의 소스](https://github.com/stepmania/stepmania/tree/825467bc/src).

**파일 선택** — 곡 폴더를 읽는 `NotesLoader::LoadFromDir`(`src/NotesLoader.cpp`)는 `.ssc`, `.sma`, `.sm` 순으로 파일이 있는지 확인합니다. 앞선 형식에 파일이 있으면 그 로더만 사용합니다. 셋 모두 없을 때만 DWI, BMS, KSF를 같은 방식으로 시도합니다.

**채보와 타이밍** — 파일 안에 여러 채보가 있을 수 있으며, 다음과 같이 읽습니다.

| 대상 소스                | 관찰한 규칙                                                                                                                                                                                                                                                |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/NotesLoaderSM.cpp`  | `#NOTES`·`#NOTES2` 태그마다 채보를 읽습니다. 곡 태그 처리기에 `BPMS`·`STOPS`가 있으며, `FREEZES`는 `STOPS`와 같은 처리기를 사용합니다.                                                                                                                     |
| `src/NotesLoaderSSC.cpp` | `#NOTEDATA`에서 새 채보를 만들고, 이어지는 채보 태그와 `#NOTES`를 읽은 뒤 곡에 추가합니다. 곡 수준의 `BPMS`·`STOPS`·`WARPS`와 채보별 처리기가 따로 있습니다. 채보별 타이밍은 파일 버전이 분리 타이밍을 지원하는 버전 이상이거나 편집 파일일 때 적용합니다. |

**채보 재선택** — `SSCLoader::LoadNoteDataFromSimfile`은 이미 있는 채보를 파일에서 다시 찾을 때 채보 종류·이름·설명·난이도·레벨·크레딧을 비교합니다. 하나라도 다르면 그 채보를 건너뜁니다. 파일 버전이 채보 이름 태그를 지원하는 버전 이상이면 `CHARTNAME`을 이름과, `DESCRIPTION`을 설명과 비교합니다. 이전 버전에서는 `DESCRIPTION`을 이름과 비교합니다.

이 재선택 규칙은 해당 로더의 동작입니다. 목록화에서 사용할 영구 식별자 규칙으로 채택한 것은 아닙니다.

### YARG: 트랙을 읽는 순서와 구현 기본값

근거: [YARC-Official/YARG.Core, `d42b96db`](https://github.com/YARC-Official/YARG.Core/tree/d42b96db).

| 대상 소스                                        | 구조를 읽는 조건                                                                                                                                            | 설정이 없을 때의 기본값                                                                         |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `MoonscraperChartParser/IO/Chart/ChartReader.cs` | 첫째 섹션으로 `[Song]`, 둘째 섹션으로 `[SyncTrack]`을 요구합니다. 없거나 순서가 다르면 예외를 던집니다. 이 조건을 통과한 뒤 나머지 악기 섹션을 읽습니다.    | `Resolution`은 192입니다. HOPO 임계는 `Resolution * 65 / 192`이며 해상도 192에서 65 tick입니다. |
| `MoonscraperChartParser/IO/Midi/MidReader.cs`    | time division이 4분음표당 tick 방식이어야 하며, 첫 트랙을 싱크 트랙으로 요구합니다. 곡 전체 이벤트를 담은 `EVENTS` 트랙을 다른 트랙보다 먼저 찾아 읽습니다. | HOPO 임계는 `Resolution / 3 + 1`입니다.                                                         |

기본값은 파일에 명시된 값과 구별해 기록해야 합니다. 위 관찰은 YARG가 읽는 일부 규칙이며, Clone Hero 등 다른 구현과의 동일성을 확인한 결과는 아닙니다.

### osu!mania: 모드와 노트 위치

근거: [ppy/osu-wiki, `85834aa`의 파일 형식 문서](https://github.com/ppy/osu-wiki/tree/85834aa/wiki/Client/File_formats).

- `Mode` 값 `3`은 osu!mania를 나타냅니다.
- 홀드 노트는 `x,y,time,type,hitSound,endTime:hitSample` 형태이며, `type`의 비트 7로 표시합니다.
- 열 번호는 `floor(x * columnCount / 512)`로 계산하고 `0`과 `columnCount - 1` 사이로 제한합니다. mania의 오브젝트는 `y`를 사용하지 않습니다.

이는 모드에 따른 노트 해석의 예입니다. 음원·배경·영상의 참조와 경로 규칙은 별도로 대조해야 합니다.

### 이 관찰로 확인하지 못한 것

- StepMania 공식 위키와 위 소스의 설명이 일치하는지
- YARG와 다른 게임·도구가 같은 입력을 동일하게 읽는지
- 배포된 실행 파일이 위 커밋의 소스와 일치하는지
- 실제 파일을 로더·게임에서 실행했을 때 어떤 결과가 나오는지

## 4. 보컬형 매체의 표기

보컬형 매체에서는 음높이·구절·트랙 같은 구별도 살펴야 합니다. 아래는 2026-10-14의 문서·소스 대조 기록이며, 마이크 입력의 분석이나 게임 실행은 포함하지 않습니다.

### UltraStar: 속성과 본문 표기

근거: [UltraStar 형식 문서](https://usdx.eu/format). 열람한 판은 1.1.0이며 문서에 표시된 갱신일은 2023-11-21입니다. 이 문서는 1.1.0만 설명하므로 이전 판이나 판 표기가 없는 파일의 취급으로 일반화하지 않습니다.

**파일 속성** — 필수 속성 목록에는 `#AUDIO`와 `#VERSION`이 있습니다. 문서는 `#AUDIO`가 `#MP3`를 대체하며 `#MP3`를 2025년에 없앨 예정이라고 설명합니다. 이 일정 표기는 열람한 문서의 설명이며, 실제 제거 여부를 확인한 결과는 아닙니다.

**본문 표기** — 노트 종류와 구절의 경계를 구별합니다.

| 표기 | 문서에서 설명한 의미                       |
| ---- | ------------------------------------------ |
| `:`  | 일반 노트                                  |
| `*`  | 황금 노트                                  |
| `F`  | 프리스타일, 점수 없음                      |
| `R`  | 랩                                         |
| `G`  | 랩 황금                                    |
| `-`  | 구절의 끝. 다음 구절의 시작 박도 함께 기록 |

**시간 기준** — 문서는 `#BPM`을 4분음표 단위로 설명하며 곡의 실제 BPM의 4배를 이상적인 값으로 제시합니다. 임의의 BPM으로 탭할 수 있으므로 실제 템포와 꼭 관련되지는 않는다고도 설명합니다. MIDI와의 비교는 이 문서에서 다루지 않습니다.

### Rock Band 계열 보컬 MIDI: YARG의 트랙·노트 해석

근거: [YARG.Core `d42b96db`](https://github.com/YARC-Official/YARG.Core/tree/d42b96db)의 `MidIOHelper.cs`.

| 구별             | 해당 구현에서 읽는 값                                               |
| ---------------- | ------------------------------------------------------------------- |
| 보컬 트랙        | `PART VOCALS`                                                       |
| 하모니 트랙      | `HARM1`~`HARM3`. The Beatles: Rock Band는 `PART HARM1`~`PART HARM3` |
| 보컬 음높이 노트 | 36~84                                                               |
| 타악             | 96(재생), 97(비재생)                                                |
| 구절 표시        | 105, 106                                                            |
| 스타 파워 노트   | 116                                                                 |

소스 주석은 Rock Band 3가 대결용 구절 표시를 없애고 보컬에서는 105만 사용한다고 설명합니다. 이 설명과 표의 값은 YARG 소스에서 읽은 내용입니다. 원 제작자의 명세나 다른 게임·도구의 동작까지 확인한 것은 아닙니다.

### 남은 확인

UltraStar 1.1.0 이전 판의 차이, Rock Band 보컬 MIDI의 원 제작 문서, Karaoke Revolution 판본별 내부 형식, 마이크 입력의 분석 방식은 확인하지 못했습니다.

## 5. 목록화·보존에서 검토할 점

비교 결과를 목록화에 사용할 때는 다음 질문으로 이어갑니다.

| 검토할 관계           | 기록하거나 더 확인할 것                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 파일과 개별 채보      | 복수 채보를 담는 파일의 식별자와 파일 안의 채보 식별을 구별합니다. BMS처럼 분기가 있는 경우에는 해석 결과를 어떤 단위로 기록할지도 확인합니다. |
| 채보와 공유 자료      | 곡 정보·음원·이미지가 별도 파일에 있는지, 여러 채보가 함께 참조하는지 확인합니다.                                                              |
| 참조 표기와 탐색 규칙 | 슬롯·태그·배열·파일명 관행을 구별하고, 원문의 참조 위치와 경로 기준을 기록합니다.                                                              |
| 원본 값과 해석 결과   | 파일에 적힌 값, 구현이 보충한 기본값, 판본·모드에 따른 해석을 구별합니다.                                                                      |
