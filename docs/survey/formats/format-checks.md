## 1. 공개 자료에서 확인한 안내

형식별 비교를 이어가기 위해 남아 있는 질문과 확인할 자료를 정리합니다. 자료의 위치를 아는 것, 명세를 읽은 것, 프로그램에서 동작을 확인한 것은 확인 수준이 다릅니다. 아래의 문서 안내를 확인한 사실만으로 해당 형식의 전체 규칙이나 구현 동작까지 확인했다고 보지 않습니다.

### simai: 문서 이전 안내와 기보 설명

2026-10-16에 simai의 [기존 문서](https://w.atwiki.jp/simai/pages/25.html)와 [현행 표기 문서](https://w.atwiki.jp/simai/pages/1002.html)를 열어 대조했습니다. 기존 페이지는 내용을 새 일본어·영어 표기 문서로 옮겼다고 안내하면서 과거 기보 설명도 남기고 있습니다.

따라서 기존 페이지에는 메타데이터 헤더와 기보 설명이 함께 있다는 점을 고려해야 합니다. 헤더와 기보 규칙을 인용할 때는 실제 설명이 있는 절과 열람 시점을 함께 적습니다. 전체 기보의 파서·실행 대조는 남아 있습니다.

### KSH: 파일 참조와 인코딩의 근거

KSH의 파일 참조와 인코딩은 [KSH 형식 명세](https://kson.dev/docs/format-spec/ksh_format/)에서 확인할 수 있습니다. 음원 참조 `m`과 이미지 참조 `jacket`은 [채보 단위와 파일 참조 필드][units]에 연결했습니다.

연결한 문서에는 명세에서 읽은 내용과 KSM 실행으로 확인하지 않은 범위를 구분해 두었습니다. 이곳에서는 같은 필드 설명을 반복하지 않고 해당 비교로 이어갑니다.

## 2. 형식별로 남아 있는 질문

표의 질문은 확인된 기능 목록이 아닙니다. 각 행에서 현재 확보한 단서와 다음에 대조할 자료를 구별합니다. 나열 순서는 상세 조사 우선순위를 확정한 것이 아닙니다.

| 대상                   | 확인할 질문                                                                      | 현재 근거·한계                                                                                                                                                       | 다음에 확인할 것                                                                       |
| ---------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| RBN / C3               | 제작 도구의 입력 MIDI·음원과 배포 묶음은 어떻게 연결되는가?                      | [Magma 문서](http://docs.c3universe.com/rbndocs/index.php?title=Magma)·[REAPER 문서](http://docs.c3universe.com/rbndocs/index.php?title=Reaper)가 조사 출발점입니다. | 대상 도구·판본을 정하고, 입력 자료와 배포 묶음을 설명하는 본문을 대조합니다.           |
| simai                  | `maidata.txt`의 헤더·난이도별 본문과 기보 규칙을 어떻게 구별하는가?              | [현행 표기 문서](https://w.atwiki.jp/simai/pages/1002.html)의 안내를 확인했습니다. 전체 기보의 파서·실행 대조는 미수행입니다.                                        | 헤더와 난이도별 기보의 설명 위치를 구별하고, 구현이 읽는 규칙과 대조합니다.            |
| PEC·RPE                | 명령형 표현과 JSON 표현 사이에 어떤 정보가 대응하며, 변환에서 무엇이 달라지는가? | [Re:PhiEdit 소개](https://pgrfm.miraheze.org/wiki/Re:PhiEdit/en)는 2차 자료입니다. 원 명세·변환기 소스 판본은 미확인입니다.                                          | 원 명세 또는 변환기 소스 판본을 확보하고 입력·출력의 대응을 확인합니다.                |
| SOUND VOLTEX `.vox`    | 판본별 좌표 범위·수치형·레이저 해석은 어떻게 다른가?                             | 직접 인용할 원 명세 또는 변환기 소스의 판본·절은 미확인입니다.                                                                                                       | 대상 판본과 근거 위치를 확보한 뒤 좌표·수치형·레이저 처리 규칙을 대조합니다.           |
| `.chart`               | 원본 FeedBack과 각 게임·도구의 확장 노트는 어떻게 구별되는가?                    | [GuitarGame_ChartFormats](https://github.com/TheNathannator/GuitarGame_ChartFormats)의 저장소 안내를 확인했습니다. 레인별 세부 규칙과 구현 대조는 미완료입니다.      | 원본 규칙과 확장을 구분하고 레인별 처리 규칙을 구현과 대조합니다.                      |
| UCS                    | 블록 헤더의 시간 단위·누적 방식과 판본별 차이는 무엇인가?                        | [UCS 사이트](https://ucs.piugame.com/)가 조사 출발점입니다. 사이트 존재·접속 상태는 명세 내용의 확인과 별개입니다.                                                   | 형식을 설명하는 문서와 대상 판본을 확보한 뒤 블록 헤더의 의미를 확인합니다.            |
| maimai ma2·`S*T`·`S*B` | 시간 단위와 컨테이너·인코딩·암호화 관계를 어떤 공개 근거로 설명할 수 있는가?     | 직접 인용할 명세 또는 소스 판본은 미확인입니다.                                                                                                                      | 각 표기의 역할을 설명할 공개 근거를 확보한 뒤 시간 표현과 자료 포장 방식을 구별합니다. |
| ADOFAI                 | 각도·템포·이벤트가 함께 작용할 때 시간과 음원 참조는 어떻게 결정되는가?          | 대상 명세 또는 구현의 판본·처리 위치를 확보해야 합니다.                                                                                                              | 시간 계산과 음원 탐색을 설명하는 문서·소스 위치를 찾아 대조합니다.                     |

좌표 범위, 암호화 방식, 시간 계산식처럼 구체적인 값은 위 질문의 답을 뒷받침하는 직접 근거를 확보한 뒤 설명합니다. 게임·판본·구현체가 다르면 같은 확장자나 비슷한 필드 이름만으로 규칙을 옮겨 적용하지 않습니다.

명세나 소스의 근거가 미확인이라는 이유로 존재가 확인된 형식을 발견 목록에서 지우지 않습니다. 자료에 접근하지 못했거나 본문을 아직 대조하지 못한 경우에는 그 범위와 필요한 근거를 남깁니다.

## 3. 확인 결과를 남기는 방법

확인 결과는 다음 항목을 갖추어 기록합니다.

| 기록 항목   | 남길 내용                                                       |
| ----------- | --------------------------------------------------------------- |
| 대상과 판본 | 형식·게임·도구의 이름과 적용 버전 또는 커밋                     |
| 공개 근거   | 문서 URL과 열람일, 해당 절·필드 또는 소스 위치                  |
| 확인 방법   | 안내·본문 열람, 소스 정적 관찰, 실행 관찰 중 실제로 수행한 방법 |
| 관찰 결과   | 읽은 규칙과 적용 범위. 파일에 적힌 값과 구현 기본값도 구별      |
| 실행 조건   | 실행한 경우에만 입력·프로그램 판본·조건·결과                    |
| 남은 질문   | 확인하지 못한 범위와 필요한 자료·확인 방법                      |

소스만 읽었다면 정적 관찰로, 프로그램을 실행했다면 실행 관찰로 구분합니다. 확인 결과는 근거가 답한 질문에 한해 갱신하며, 일부 필드를 읽은 결과를 형식 전체의 지원이나 변환 충실도 확인으로 확대하지 않습니다.
