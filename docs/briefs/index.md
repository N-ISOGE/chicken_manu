# 의뢰서 모음

다른 AI 어시스턴트(Perplexity, ChatGPT, Gemini 등)에게 조사를 맡길 때 넘기는 문서를 모아 둔 곳이다.
의뢰서 하나는 주제 하나이고, 그 문서만 읽어도 시작할 수 있게 쓴다. 작성 기준일은 2026-10-08이다.

상태와 "넘김" 여부는 사용자가 직접 갱신한다. 결과를 받으면 어디에 두었는지도 이 표에 적는다.

## 공통 규칙

모든 의뢰서와 함께 이 절을 넘긴다. B-01은 사실 수집용이라 이보다 엄격한 규칙(그 문서 2절)이 따로 있다.

1. **1차 출처 우선.** 공식 사이트, 원문 논문, 법령 원문, 소스 저장소 순으로 쓰고 2차 자료는 따로 표시한다.
2. **추측 금지.** 확인하지 못한 값은 `미확인`과 이유(HTTP 상태, 유료 장벽, 폐쇄 등)를 적는다. 비슷해 보이는 값으로 채우지 않는다.
3. **확인 상태와 신빙성을 분리한다.**
   - 확인 상태: `확인`(원문을 직접 열어 확인) / `부분`(일부만 읽음, 요약 결과에 기댐) / `미확인`.
   - 신빙성: A(공식·1차) / B(신뢰할 만한 2차, 구현체 문서) / C(비공식, 오래된 글) / X(제외).
4. **의뢰서에 적힌 인명, 문헌명, 기술 주장은 검증 대상이다.** 사용자의 기억이나 작성자의 일반 지식에서 온 것이라 틀릴 수 있다. 어긋나면 어긋남을 적는다.
5. **원어를 보존한다.** 출처가 쓰는 용어를 그대로 적고 한국어 설명과 원어를 병기한다. 통일은 하지 않는다.
6. **날짜를 적는다.** 모든 항목에 확인일(YYYY-MM-DD)을 적는다.
7. **짧게 인용한다.** 한두 문장, 한 함수명 정도만 옮긴다. AI가 자동 생성했을 가능성이 있는 사이트(`deepwiki.com`, `*.mintlify.app` 자동 문서, `grokipedia.com` 등)는 근거로 쓰지 않고 "제외 출처"로 기록만 한다.
8. **실행하지 않는다.** 내려받은 실행 파일을 실행하지 않는다. 문서와 소스를 읽는 것으로 한정한다.
9. **사실과 제안을 구분한다.** 제안을 허용한 의뢰서에서도 제안에는 `[제안]` 표시를 붙이고 근거를 함께 쓴다. 결정은 사용자가 한다.
10. **형식.** 한국어, 마크다운, 표와 목록 중심. 코드 블록에는 언어(`text` 등)를 적고, 대괄호 표기는 백틱으로 감싼다.

## 공통 보고 형식

작업을 마치면 한 번에 보고한다.

1. 만든 문서 목록과 각 문서의 한 줄 요약.
2. 접근하지 못한 대상과 이유.
3. 의뢰서의 내용과 어긋난 사실.
4. `[제안]` 목록(제안을 허용한 경우).
5. 사용자가 정해야 할 질문.
6. 다음에 조사할 만한 대상.

## 새 의뢰서 추가

1. `docs/briefs/<slug>.md`를 만든다. 넘기기 전에 읽는 법(공통 규칙을 같이 넘길 것)을 맨 위에 적는다.
2. `src/docs.rs`의 `briefs` 모듈에 `pub mod`를 하나 추가한다.
3. 위 목록 표에 한 줄을 더한다.
