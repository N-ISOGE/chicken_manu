# 의뢰서 B-02: 매체의 정의

넘길 때 [의뢰서 모음](crate::docs::briefs)의 **공통 규칙과 공통 보고 형식**을 같이 넘긴다. 작성 기준일은 2026-10-08이다.
이 의뢰서는 **제안을 허용한다**(공통 규칙 9). 결정은 사용자가 한다.

## 1. 배경

- 프로젝트: `chicken_manu`(치킨메뉴). 리듬게임·음악게임의 **매체**를 조사하고, 매체를 공유·보존하는 데이터 포맷, 스키마, Rust 도구를 만든다.
- 용어(프로젝트의 현재 합의):
  - **매체**: 리듬게임·음악게임의 플레이를 규정하는 데이터. chart, 譜面, 보면, beatmap, simfile, level 등 출처마다 이름이 다르다.
  - **에셋**: 매체가 **참조하는** 파일(음원, 키음, 이미지, 영상 등). 매체에 속하지 않고 바깥에 있다.
  - 매체와 에셋의 관계가 **파일 참조**이다.
- 아직 정하지 못한 것: **매체의 구성과 형식**. 무엇이 매체의 부분이고 무엇이 아닌지, 매체를 어떤 층위로 나눠 설명할지.
- 사용자는 이 정의에 에스펜 올셋(Aarseth)과 고든 체레자의 **사이버미디어 모델**을 참조하겠다고 했다.
  이 표기는 사용자의 기록 그대로이며, 어떤 문헌인지 이 프로젝트는 확인하지 못했다.

## 2. 요청

1. 사용자가 말한 사이버미디어 모델의 **문헌을 식별하고 원문을 확인**한다.
2. 그 모델이 매체의 **구성 요소와 층위**를 어떻게 나누는지 원문 용어로 정리한다.
3. 정리한 틀에 이 프로젝트의 매체 포맷을 **대응시켜 보고**, 매체의 구성과 형식에 대한 **정의안을 제안**한다.

## 3. 먼저 할 일: 문헌 식별

아래는 **찾기 위한 단서이며 검증된 사실이 아니다**(작성자의 기억이다). 맞는지 먼저 확인한다.

| 단서 | 비고 |
| --- | --- |
| Espen Aarseth, *Cybertext: Perspectives on Ergodic Literature* (1997) | 책의 서지 사항과 핵심 개념(원문 용어)을 확인할 것 |
| Espen Aarseth, Gordon Calleja, "The Word Game: The Ontology of an Indefinable Object" (2015) | 두 사람의 공저로 기억함. 연도와 게재처를 확인할 것 |
| "고든 체레자" | 사용자의 표기. Gordon Calleja와 같은 사람인지, 다른 표기인지 확인할 것. 확인하지 못하면 `미확인`으로 둔다 |
| "사이버미디어 모델" | 어느 문헌의 어느 부분을 가리키는지 확정되지 않았다. 후보를 나열하고 근거를 붙인다 |

- 사용자가 말한 "사이버미디어 모델"에 해당하는 문헌을 **찾지 못하면** 비슷한 다른 문헌으로 대체하지 않는다. 찾지 못했다고 보고하고, 후보를 `[제안]`으로 따로 적는다.
- 판본, 쪽수, 장 번호, DOI/ISBN은 확인한 것만 적는다.

## 4. 함께 살펴볼 비교 대상 (제안)

프로젝트는 매체를 **도서관의 목록처럼** 관리하는 도구를 목표로 한다. 그래서 서지 모델도 비교 후보다. 아래도 작성자의 기억이므로 검증 대상이다.

- FRBR / IFLA LRM의 Work, Expression, Manifestation, Item 층위. (이 프로젝트의 이전 문서가 "표현"이라는 말을 쓴 것과 겹치는지 확인할 것.)
- 그 밖에 게임 연구에서 게임 텍스트나 게임 산물의 층위를 나눈 모델이 있으면 `[제안]`으로 추가한다.

## 5. 대상마다 답해야 할 질문

| 번호 | 질문 |
| --- | --- |
| M1 | 사이버미디어 모델은 매체를 어떤 구성 요소와 층위로 나누는가. 각 요소의 **원어 용어**와 정의(짧은 인용) |
| M2 | 그 요소 중 이 프로젝트의 **채보 파일**이 담는 것은 무엇이고, 담지 않는 것은 무엇인가 |
| M3 | BMS(`.bms .bme .bml .pms`), `.chart`, `.osu`, `.sm`, `.ssc`를 모델의 요소에 대응시킨 **초안 표**. 포맷마다 시간 기저(마디 격자, 틱, 절대 시간 등)와 구조가 다르다는 점을 반영한다 |
| M4 | 아래 경계 후보를 매체 **안**으로 볼 근거와 **밖**(에셋 또는 별개)으로 볼 근거. 각각 모델의 어느 요소로 설명되는가 |
| M5 | 매체와 에셋의 **참조 관계**를 모델로 어떻게 설명할 수 있는가. 같은 매체가 에셋을 바꿔 가며 존재하는 경우(예: 음원 교체)를 포함한다 |
| M6 | 한 파일에 매체가 여러 개 들어가는 경우(한 파일 여러 난이도)와 매체 하나가 파일 여럿에 나뉘는 경우를 모델은 어떻게 다루는가 |
| M7 | 모델의 개념을 메타데이터 스키마의 항목(예: 묶음, 패턴, 파일, 제작 참여자)으로 옮길 때 생기는 **빈틈과 충돌** |

### 경계 후보

| 후보 | 설명 |
| --- | --- |
| 리플레이 | 플레이 결과를 기록한 파일(예: osu! `.osr`) |
| 스토리보드 | 영상·그림의 진행을 기술한 스크립트(예: osu! `.osb`) |
| 스킨 | 화면 표현을 정하는 자료(예: LR2 skin csv) |
| 난이도표 | 채보를 모아 등급을 매긴 목록(예: BMS 난이도표) |
| 곡 메타데이터 | 곡명, 제작자, 장르 등. 채보 안에 있기도 하고 별도 파일(`song.ini` 등)에 있기도 하다 |

## 6. 산출물

`docs/` 아래에 넣을 마크다운 문서로 낸다.

1. 문헌 식별표: 단서별로 확인 결과, 서지 사항, 확인 상태, 신빙성, 확인일.
2. 모델 요약: 요소별 원어 용어, 한국어 설명, 짧은 인용, 출처 위치.
3. M3의 대응 초안 표(포맷 × 모델 요소).
4. 매체 정의안 `[제안]`: 구성 요소, 형식, 경계를 몇 가지 안으로. 안마다 장단점과 근거.
5. 열린 질문: 문헌만으로는 정할 수 없는 것들.

## 7. 하지 말 것

- 문헌을 읽지 않고 모델의 내용을 설명하지 않는다. 읽지 못한 문헌은 `미확인`이다.
- 서로 다른 포맷의 요소를 같은 것으로 합치지 않는다. 대응은 표에 기록만 한다.
- 에셋을 매체에 포함하는 안을 기본으로 삼지 않는다. 필요하면 별도 `[제안]`으로 쓴다.
- 이론을 이 프로젝트에 끼워 맞추려고 원문의 뜻을 바꾸지 않는다. 맞지 않는 부분은 맞지 않는다고 적는다.
