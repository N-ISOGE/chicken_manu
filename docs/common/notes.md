## 1. 문서 작성

### 구성과 표기

한 문서는 하나의 주제를 다룹니다. 제목과 목차에서 필요한 내용의 위치를 찾을 수 있도록 구성하고, 하위 문서는 상위 목차에서 연결합니다.

매체의 이름과 형식 식별자, 필드·명령 이름은 출처의 원어 표기를 유지합니다. 한국어 설명과 대응 관계는 별도로 적습니다.

### 근거와 적용 범위

확인한 내용에는 출처와 판본, 적용 범위를 함께 적습니다. 명세의 설명, 특정 구현에서 관찰한 동작, 실행으로 확인한 결과를 구별합니다. 확인하지 못한 사항은 남은 질문으로 표시합니다.

### 문서 사이의 참조

문서 링크는 GitHub의 Markdown 원본과 rustdoc에서 모두 이동할 수 있도록 작성합니다. Markdown에는 상대 경로의 참조형 링크를 사용하고, 해당 문서를 싣는 Rust 모듈에는 같은 참조 이름으로 rustdoc 대상 경로를 정의합니다.

문서를 옮기거나 절 제목을 바꾸면 그 문서를 가리키는 링크도 함께 확인합니다.

## 2. 문서 검증

### 문서 빌드와 링크

저장소 루트에서 다음 명령으로 rustdoc을 생성합니다.

```sh
cargo doc --no-deps
```

생성한 문서에서 목차와 문서 사이의 링크를 확인합니다. Markdown 원본의 상대 링크와 절 이동 링크도 함께 살펴봅니다.

### 서식과 내용

Markdown의 제목·목록·표·코드 블록이 올바르게 표시되는지 확인합니다. 서식 수정과 함께 문장이나 표의 값이 달라지지 않았는지 변경 내용을 대조합니다.

Rust 파일의 문서 주석이나 모듈 선언을 수정했다면 Rust 서식도 확인합니다.

```sh
cargo fmt --check
```

## 3. 코드 검증

### 컴파일과 정적 검사

코드와 테스트가 컴파일되는지 확인하고 정적 검사를 실행합니다.

```sh
cargo check --tests
cargo clippy --all-targets -- -D warnings
```

### 동작 확인

동작을 바꿨다면 관련 테스트를 실행합니다.

```sh
cargo test
```

Rust 코드를 수정했다면 `cargo fmt --check`로 서식도 확인합니다.

### 결과와 한계 기록

컴파일 확인과 테스트 실행 결과는 구별합니다. 네이티브 라이브러리 등 필요한 실행 조건이 없어 검사를 마치지 못했다면, 실행한 검사와 미실행 이유를 함께 기록합니다.
